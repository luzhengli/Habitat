# 03 · Habitat Air 的 Web 视觉规范

## 方向不变

继续采用已确认 Air：浅银灰侧栏、白色内容区、少量蓝色交互强调、细边框、系统字体、用途优先卡片、适度留白。保留 Refero Apple/Dub 参考的精神，不重新抓一套主题。参考链接见 09。

本包 `design/` 与 `reference/air/Habitat-Air.html` 是原 Air 证据，原件保持不变；其桌面壳标记是历史，不是 Web 实现需求。`apps/web/src/web.css` 是最小 Web 覆盖示例，不是完成全部视觉复验的声明。

## 从桌面改成 Web 必须改变的部分

删除 DESKTOP PREVIEW、原生 titlebar 预留、Mac 三键安全区、data-tauri-drag-region、shellMode 分支。不要为了和旧截图一模一样保留无功能的顶部空白。

使用普通导航链接及可复制的 URL。页面深链/后退/刷新由路由处理，不把所有页塞进一个无法恢复的局部布尔值。保留草稿提示但尊重浏览器导航。

平台快捷键显示基于访问端。不要保留原型 Cmd/Ctrl+1–4 的页面切换，这会抢浏览器标签页；提供侧栏和可配置搜索。

系统字体栈 `-apple-system, BlinkMacSystemFont, Segoe UI, sans-serif`；中文依系统回退。等宽 `ui-monospace`。不捆绑字体文件，尤其不分发 Apple 字体。

## 信息层级

卡片：名称/来源 → 一句话用途 → 使用位置/必要状态/常显“使用”。详情：用途→用法→来源与使用→文件→版本/环境。路径、Hash、事务ID进入技术详情；出错时对应证据可展开。

同一区域一个主要蓝色动作。无变化时不显示待应用栏；有草稿时稳定显示受影响技能数量及预检入口。状态不可只靠颜色；已配置中性，未知与警告明确标注，不能用绿色证明运行成功。

正常输入不塞过多解释，只有收录/写入差异、全局影响、取消和危险操作才展开上下文提示。设计中的留白不是减少功能，而是减少默认展示的重复信息。

## 交互状态

卡片常显使用；禁用说明有文字/tooltip且可键盘读到。hover只强化，不是发现入口的前提。控件有 loading/disabled/focus/selected；模态有标题、关闭、焦点循环、Esc和焦点恢复。140ms左右轻量动效，尊重 reduced-motion。

XSS 防护先于 Markdown 还原：正文渲染不用 raw HTML；代码内容使用文本节点；外部图片/脚本不自动加载。用户名字和路径要测试 HTML 字符、超长、Emoji和中文；不是所有文本都可按slug处理。

## 视觉验收

同样数据、视口、状态对比库、详情、项目、添加、确认、诊断、历史、设置。先修复入口不明显、过密、文本截断、遮挡和焦点丢失，再处理轻微阴影/字形差异。记录 Web 与旧桌面截图的有意变化，不把合理移除 titlebar 算成回归。

Chromium 截图≠Safari验证；响应式390px≠移动系统目录授权已支持；截图相似≠安装事务安全。
