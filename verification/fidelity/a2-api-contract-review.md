# A2 failure-state API contract review

Reviewed 2026-09-22. Scope is the unapproved A2 candidate's 17 `FAILURE_SCENARIOS` entries against the current service code. This is a static semantic review only: no candidate preview, browser, API request, filesystem mutation, or full gate was run. The candidate remains synthetic and is not production evidence.

## Result

The state grouping, the protected-operation model, and all 17 intended recovery directions are largely aligned. Four wording/status corrections are required before the candidate can be presented as a faithful representation of the current service. They do not authorize production implementation.

| Priority | Candidate state and mismatch | Current service evidence | Required candidate correction |
|---|---|---|---|
| P1 | `git-quota` displays `INTERNAL_ERROR · GitHub HTTP 403`, but current API clients cannot observe that upstream `403`. The service maps the plain upstream error to **HTTP 500 / `INTERNAL_ERROR`** and replaces its message with a generic service-state message. | `githubJSON` creates a plain `Error` for a non-200 response at [git-source.mjs:17](../../apps/server/git-source.mjs#L17). The HTTP boundary returns `500 INTERNAL_ERROR` and uses the generic message whenever `e.status` is absent at [app.mjs:166](../../apps/server/app.mjs#L166). | Present only “当前服务未细分原因的 INTERNAL_ERROR（HTTP 500）”. If a 403 example is retained for design exploration, label it as an unproven synthetic setting rather than current API evidence. Keep the existing no-credentials/no-auto-retry claims. |
| P1 | `package-rejected` does not state the actual service status. `GIT_LIMIT` and `UNSAFE_GIT_ENTRY` are domain errors with the default **HTTP 422**, not a common bespoke Git response. | Validation at [git-source.mjs:39-45](../../apps/server/git-source.mjs#L39) passes no status to `requireValue`; its default is 422 at [catalog.mjs:8-11](../../apps/server/catalog.mjs#L8). | Add `· 422` to the badge or supporting text. Preserve the refusal to partially accept a package. |
| P2 | `network-failed` says the download candidate is “未创建”; `package-rejected` says no partial result remains. Neither should promise that the isolated `downloads/<uuid>` working directory is absent after a failure during blob retrieval. A catalog `git-candidate` record is only written after all blobs and the manifest complete. | Work directory creation precedes blob retrieval at [git-source.mjs:46-48](../../apps/server/git-source.mjs#L46); the durable candidate record is written only at [git-source.mjs:50-52](../../apps/server/git-source.mjs#L50). | Qualify both as “未创建可收录候选记录/未产生来源收录或项目切换”; do not promise cleanup of an incomplete isolated download directory. |
| P2 | `detail-binary` says Habitat “不解码”. The service deliberately performs a strict UTF-8 decode in order to reject invalid bytes; it still does not execute or upload the content. | File content is strictly decoded at [skill-files.mjs:13-14](../../apps/server/skill-files.mjs#L13); a decoding failure returns `UNSUPPORTED_BINARY` (422), while all file accesses are limited to the manifest at [skill-files.mjs:7-12](../../apps/server/skill-files.mjs#L7). | Replace “不解码” with “只尝试严格 UTF-8 文本解码；失败时不展示正文”. |

## Contract boundaries retained by A2

- The candidate correctly keeps all controls synthetic: its picker and overlay state only mutate browser state and explicitly make no API, network, or local-file call ([FailureStates.jsx:33-35](../../design/prototype-revisions/A2-failure-states/src/components/FailureStates.jsx#L33), [FailureStates.jsx:46-58](../../design/prototype-revisions/A2-failure-states/src/components/FailureStates.jsx#L46)).
- A `succeeded` operation proves project-entry readback and fixed-copy integrity; it does **not** prove Agent discovery or invocation ([operations.mjs:154-158](../../apps/server/operations.mjs#L154)).
- This review is not user confirmation of A2 and does not make the candidate a production baseline.
